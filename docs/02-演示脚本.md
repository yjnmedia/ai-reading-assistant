# 10 分钟演示脚本

照着做，五步能看出这套东西到底做了什么。全程只用公开数据和本机环境。

## 1. 先看规模问题（1 分钟）

一本 397 万字的书 ≈ 290 万 token，是 256k 上下文窗口的 11 倍。
把书直接塞给模型这条路当场就断了——这一步不用装任何东西，算一下就知道。

## 2. 建索引（5~8 分钟，可跳过）

按章切分 → 每章一条 150~200 字摘要 → 每 10 章聚合一条 250~350 字。
889 章 + 89 条聚合，978 次调用，批量价约 5.4 元。
索引结果落本地 SQLite：章摘要、人物/事件/场景表、全文片段。

## 3. 依次点三个页签（2 分钟）

选中一段，先看「解释这段」：只解释本段真有疑问的点，末尾给虚拟等级；
再点「为什么」：一句因果 + 来龙去脉 + 依据，材料只取到当前位置之前；
最后点「前文线索」。
它会先认出这段里的 2~5 个人名或物件，再逐个去索引里查首次出现与最近提及，只给当前章之前的原文片段。

## 4. 验证不剧透（1 分钟）

问一个后文才有的名字。
意料之中的结果：**回答「前文没找到」，而不是把后文内容说出来**。截断发生在 SQL 层，不靠提示词自觉。

## 5. 断网验证（1 分钟）

手机开飞行模式，继续翻页、继续看书。
行为：照常阅读，只有「问书」不可用；恢复网络后自动恢复，不弹窗、不丢进度。

---

做不到的部分也说清楚：这套流程需要一台长期开机的机器放索引，首次建库有一次性成本（约 5.4 元/本）。
