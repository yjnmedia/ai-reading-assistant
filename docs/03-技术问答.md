# 技术问答

**Q：为什么不用向量数据库？**
A：用得上，但不是第一优先级。这类问题多数是「某个人/某件事在前文怎么写的」，先用人物与事件表 + 全文检索就能答；向量召回留作补充，避免一开始就引入 embedding 的运维与成本。

**Q：为什么不把整本书上传给模型？**
A：算不下来。397 万字约 290 万 token，是 256k 窗口的 11 倍；而且每次提问都重复付费。离线索引把一次性成本压到约 5.4 元/本，单次问答约 0.03 元。

**Q：怎么保证不剧透？**
A：三道：①客户端只发位置与短片段，不发整章；②服务端按章硬截断（`ch_global < 当前章`），提示词只是第三道；③跨版本靠「当前位置前 200 字」定位，而不是章号（实测章号法最多越界 92.2%）。

**Q：同一本书不同版本怎么认？**
A：4096 个 9-gram 最小哈希做相似度，≥0.90 判同书。实测同书异版 0.9956、不同书 0.0000。阈值区间：0.60~0.90 交人工确认。

**Q：能直接给我装一个吗？**
A：这个仓库放的是方案与实测数据，不含可直接安装的客户端。索引与问答服务需要在你自己的机器上跑（一台长期开机的电脑即可）。

**Q：许可与商用？**
A：本仓库文字与图为原创，可引用并注明出处。文中提到的第三方模型、词表等按其各自许可使用；不包含任何第三方客户端代码。
