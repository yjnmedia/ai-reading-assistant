# 技术问答（可能会被问到的问题）

## 1. 为什么不用向量数据库？

因为要解决的问题不是「语义相似」，而是**精确定位 + 绝对不越界**。向量检索只能给「相似的段落」，无法保证「不包含第 N 章之后的内容」；而剧透是零容忍的。

实际做法：

- 客户端上报「当前位置前 200 字」→ 服务端做唯一定位 → 拿到内部章号；
- 检索时用 SQL 硬条件 `ch_global < 当前章`，模型拿到的材料物理上不含后文；
- 章摘要与实体时间线都存在 SQLite 里，60 MB 级别，一条查询毫秒级。

## 2. 为什么不让手机把整本书上传？

- 一本 397 万字的书约 2.9M token，上传与计费都不现实；
- 更重要是隐私：书的内容不出家门。云端只做密文转发，TLS 在家里那台电脑上终止。

## 3. 怎么保证不剧透？

三道，前两道是硬的：

1. 客户端只上报位置（前 200 字），不把「读到第几章」当唯一依据；
2. 服务端 SQL 硬截断 `ch_global < 当前章`；
3. 提示词里再写「只依据当前位置之前的内容」。

## 4. 同一本书的不同版本怎么认？

书名 + 作者规范化建候选桶，桶内用 **MinHash/KMV 4096 个最小 9-gram** 算相似度：

- ≥0.90 判同书；0.60~0.90 待确认；<0.60 不同书。
- 实测：同书异版 **0.9956**，两本不相干的书 **0.0000**。

## 5. 为什么同一段解释要给两个模型？

因为两家模型的「敢说程度」不一样，这不是提示词能压住的。实测同一段写回扣、串供、陪酒的情节：

- 豆包会往概念上解释，把受贿说成「商业贿赂」，绕开「普遍／罪名／性化」；
- DeepSeek 直说性质与后果，点出罪名和当年的普遍程度。

所以两份都留，设置里可切，默认 DeepSeek。**代价**：一份提示词要维护两遍，改一边必须同时改另一边。

## 6. 为什么提示词里专门写「不替任何一方辩护」？

早期版本要求每条解释都硬套「小说里……／现实里……」，结果读起来像在给体制辩护（把明显的违规写成「个别现象」）。改成：原文写到什么就说什么性质、按什么规定属于违规，不加平衡话，也不反向嘲讽。

## 7. 为什么把生图放在电脑端，而不是直接用云端画图服务？

四个原因：

1. **显卡在自己手里**：模型与权重不出门，成品图不回传第三方；
2. **不用养常驻 GPU 实例**：一张一张按需排队，闲置零成本；
3. **和检索共用一条通道**：客户端只多一个「提交任务」，不新增网络面与证书；
4. **可控**：画质档位（30/40/50 步）、尺寸（480p~4K）、内容策略（涉未成年一律拦截）都能在自己这侧定。

代价是要一台带显卡、长期开机的机器，且一张图 40 秒到几分钟——所以才做「提交即返回、可连提多张」。

## 8. 创作页的图和段评配图有什么区别？

| | 创作页 | 段评配图 |
|---|---|---|
| 输入 | 自由的一句画面描述 / 上传图反推提示词 | 书里选中的那段原文 |
| 角色一致性 | 不带角色卡，每次独立 | 带角色卡（定妆多版本）+ 出场画面归属 |
| 去处 | 图库（可存相册） | 挂在该段的段评，点「前往」跳回原段 |

两者共用同一套生图服务与提示词规则，区别只在「有没有角色参考」。

## 9. 一张图反推出提示词，靠谱吗？

实测能用：多模态模型能稳定输出「主体、服饰、姿态、环境、光线与色调」这类可复用的描述，改两个字再生成，风格大体延续。

但它**不是等比复刻**：构图与细节会变，人脸也不会一致（没有参考图机制）。定位是「把别人的好句子变成自己的起点」，不是「复制这张图」。
