# 长篇小说 AI 阅读助手 · 方案说明

> 面向：对「边读边问、不剧透」有需求的长篇内容平台（网文、连载、大部头）。
> 本文只讲方案与实测数据，不包含任何客户端程序代码。

---

## 1. 要解决的问题

长篇连载的读者有三个具体痛点，现有产品都没解决：

1. **看不太懂**：官场、军事、年代文里的人情与体制语境，读者要反复回翻。
2. **记不住**：几百万字之后，某个人物/物件第一次出现在哪、上次提到是什么时候，读者自己查不动。
3. **不敢查**：手机上搜一下，很容易搜到后文的剧透。

通用做法是把书塞进大模型上下文，但装不下：
《重生之官道2026》实测 11,436,176 字节 / 3,974,713 字符，折算约 **2.9M tokens**，
是 256k 上下文窗口的 **约 11 倍**，换成 1M 窗口也不够一本千万字的书。
**结论：必须离线建索引，在线只取「读者当前位置之前」的一小段材料。**

除此之外还多一个需求：读者想看图——这段写得带画面，希望直接看到画面，而不是自己去找图。

---

## 2. 方案结构

三层，全部可复用、与客户端无关：

```
读者（手机 App / 小程序 / 网页）
        │  ①当前位置前 200 字 + 问题 / ②一句画面描述 或 一张图
        ▼
云服务器（只做密文转发，不解密）
        │  ③mTLS 双向证书
        ▼
家里/机房的服务进程（24 小时开机的普通 PC 即可）
        ├─ 本地索引库（按章摘要 + 实体时间线，SQLite）
        ├─ 检索：先定位读者位置 → 只取该位置之前的材料
        ├─ 调用大模型生成解释（不把整本书发给模型）
        └─ 生图：写词调大模型，画图在本机显卡上跑
```

关键点：

- **索引在家用级机器上**：一台常年开机的 PC，8 核 / 16G 内存即可，索引 60 MB 级别。
- **云端零信任**：云只做 TCP 转发，TLS 在家里终止，云端看不到正文，也不存任何书。
- **断网不影响阅读**：上报与查询都是「失败即静默」，不弹窗、不阻塞翻页。
- **生图也在同一台机器**：写词走大模型 API，画图用本机显卡；成品图不出家门，只回给本人。

## 3. 核心能力

### 3.1 防剧透的定位（这是整个方案的地基）

不能靠「第几章」定位：同一本书的不同版本（连载版 / 精校版 / 合并版）章号会错位。
实测反例：某版本按章号 1441 去另一版本取材料，只到对方第 748 章，**越界 693 章 = 全书 92.2%**。

做法：客户端只上报「**当前位置前 200 字原文**」，服务端在索引里做唯一定位，得到内部章号；
检索时用 SQL 硬条件 `ch_global < 当前章` 截断，模型拿到的材料物理上就不含后文。
提示词里的「不要剧透」只是第三道保险，不是唯一防线。

### 3.2 跨设备认同一本书

同名不同书、同书不同版本都要能认出来：

- 书名 + 作者规范化建候选桶；
- 桶内用 **MinHash/KMV（4096 个最小 9-gram 哈希）** 比对；
- 阈值：≥0.90 同书，0.60~0.90 待确认，<0.60 不同书。

实测：同一本书两个版本相似度 **0.9956**，两本毫不相干的书 **0.0000**（连字符数相同的截断异书也是 0）。

### 3.3 三档解释（按需要给，不一次性倒出来）

| 档位 | 取什么材料 | 给什么 |
|---|---|---|
| 解释这段 | 本段 + 本章前文 | 只解释本段真有疑问的点（身份职务、制度规矩、行业惯例、人情关系、时代背景），最多 3 条、350 字内；末尾一行「虚构等级：强艺术虚构／轻度艺术加工／基本贴合现实常识」 |
| 为什么 | 上一章全文 + 本章前文 | 因果三段：一句「因为…」+「来龙去脉」+「依据（本段／本章前面）」 |
| 前文线索 | 家里索引库，`ch_global < 当前章` | 人/物首次出现与最近提及的章号与原句，可点回原章 |

设计原则（踩过坑之后的结论）：

- **默认少给**：解释最多 3 条、350 字内；通用官职、常见机构不解释。
- **不替任何一方辩护**：原文写到违规、腐败、权色交易，就如实说是什么性质、按什么规定属于违规；不加「大多数是好的」「个别现象」这类平衡话，也不反向嘲讽。
- **「为什么」必须整章**：实测只给「上一章末 1000 字」时，回答的充分性没有提升（lack 5→5），必须给上一章全文才能补上因果。
- **不做「读者画像问卷」**：业界没有靠首次问卷调解释粒度的先例；唯一直接对照实验（PLAI, MuC 2026）显示画像组与无画像组知识测验无显著差异。

### 3.4 两家模型共用一份提示词

解释通道不绑定单一供应商：DeepSeek（`deepseek-chat`）与豆包（方舟 `ep-` 接入点）用**同一份提示词**，客户端一键切换。

实测同一段落（回扣、串供、陪酒三类情节）：豆包系统性地往概念上解释，把受贿说成「商业贿赂」、绕开「普遍／罪名／性化」；DeepSeek 直说性质与后果。差别不在提示词，在模型本身——所以两份答案都留，让读者自己选。

> 工程约束：改提示词必须两边同时改。只改一边，同一段落会答成两种风格。

### 3.5 AI 生图（两条链路，一套机器）

同一台电脑上跑两条生图链路，区别只在「有没有角色卡」：

| | 段评配图 | 创作页 |
|---|---|---|
| 入口 | 书内长按选中一段 →「AI 生图」 | 底部「创作」页 |
| 输入 | 选中段落原文 + 上下文 | 一句中文画面描述 / 一张上传图 |
| 角色一致性 | 有：角色卡（定妆多版本）+ 出场画面归属 | 无：自由创作，不带角色 |
| 去处 | 挂在该段的段评里，可点「前往」跳回原段 | 落在创作页「图库」，可存相册 |

**为什么画图放自己机器，不放云端**

- 显卡在本机，模型与权重不出门；成品图不回传第三方；
- 一张一张按需排队，不用养常驻 GPU 实例；
- 与检索共用同一条 mTLS 通道，客户端只多一个「提交任务」，不新增网络面。

**提示词工程（三段式落地）**

1. **五段规则**：主体（谁、年龄、发长、五官）→ 服饰（颜色、材质、款式细节）→ 姿态 → 环境与光线；下体、敏感部位这类「具体到什么程度」写在第三段，避免污染前两段的着装描述。
2. **写词模型与画图模型分工**：写词模型只负责「把中文说清」，不负责画；有歧义时以五段规则兜底。
3. **成人向内容策略由服务端统一控制**：客户端只透传一句「修改意见」，由服务端按关键字决定要不要写进图面提示词；涉未成年人的内容一律拦截，不进入画图环节。

**提交即返回、可连提多张**

生图耗时从 40 秒到几分钟，等一张画完才能提下一张，体验很差。做法：

- 提交接口立刻返回任务号，客户端转圈 1 秒就变「已提交，正在画…·已等 N 秒」；
- 连着提三张就是三条任务，底部显示「正在生成（1/3）→（2/3）→（3/3）」，画完一张自动进图库；
- 图库对未完成的任务给占位块（转圈 + 已用 N 秒），失败给红块 + 原因 + 删除。

**尺寸与画质分档**

短边 480p / 720p / 1080p / 1440p / **4K（2160p）**，长边按画幅（3:4、9:16 等）换算并对齐到 16 的倍数；画质分 快速 30 步 / 标准 40 步 / 质量 50 步。默认 720p + 标准，一张约 43 秒。

## 4. 实测数据

### 4.1 索引成本（《重生之官道2026》，889 章去重后）

| 项 | 数值 |
|---|---|
| 章摘要 | 889 条，每条约 150~200 字 |
| 上层聚合 | 89 条（每 10 章一条），250~350 字 |
| 调用次数 | 978 次 |
| token | 输入 2,887,242 / 输出 148,218 |
| 费用（批量/flex 价） | **约 5.44 元** |
| 建库耗时 | 5 并发约 25~30 分钟 |

对比：把「5 章合成一条摘要」能省的钱只有 **4.7%**，但问答正确率从 8/8 掉到 3/8、
章号定位从 8/8 掉到 2/8 —— 所以**不做粗粒度合并**。

### 4.2 在线问答

- 「解释这段」（本段 + 本章前文，约 6.6k token）实测 **6.9 秒 / 约 0.011 元/次**；
  「前文线索」（取前文若干片段 + 生成）实测 **约 0.03 元/次**，延迟 0.1~3 秒（不含模型思考）。
- 关掉「深度思考」后，模型出文从 51.4 秒降到 **5.5 秒**（同一条提示词）。
- 通道实测：带客户端证书 `GET /api/ask?q=唐逸&upto=1237` → `ok=true`、**127 ms**、817 字。

### 4.3 生图

- 720×1280 / 标准 40 步：**约 43 秒**一张；快速 30 步约 34 秒；质量 50 步约 55 秒；4K（2160 短边）分钟级，适合画完直接存相册的封面图。
- 并发：连提三张不阻塞，进度按「k/n」推进；同一段重复提交会被拒绝并提示「这张已经画完了；想重画请写一句修改意见」。
- 图库规模（本机实测）：**274 个角色**、上千张图，全在本地生成与存放；老图若原文已失效，卡片显示「位置未知（没存原文）」而不是乱跳。
- 「图片转提示词」：相册一张图 → 多模态模型输出中文五段描述（实测能稳定描述服饰、姿态、环境、光线与色调），可直接改完再出图。

### 4.4 稳定性

- 家里服务进程被杀后，看门狗 **45~70 秒**自动拉起（实测多次）。
- 手机断网时切章，日志只有一行 `report failed`，界面无弹窗，阅读不受影响；联网后自动恢复。
- 云端持证访问 `/health` 200；不带证书握手直接失败（mTLS 生效）。

## 5. 接入与交付边界

**可交付（本项目自研，不含第三方代码）**

- 索引构建管线：分章、摘要、聚合、实体时间线、SQLite 结构。
- 检索与问答服务：位置定位、前文截断、三档解释的提示词与参数。
- 生图链路：五段规则与写词提示词、任务排队与状态、图库与角色卡数据结构。
- 通道设计：云转发 + 家里 mTLS 的部署方式与运维脚本说明。
- 成本模型与验收指标（每 300 字条数、被解释词难度分布、通用词占比=0）。

**不包含**

- 阅读器客户端程序与安装包（客户端基于开源阅读器改造，仅作演示，不对外分发）。
- 任何第三方库源码、模型权重。

## 6. 演示脚本（约 10 分钟）

1. 打开书，翻到某一章，长按选中一段 → 「解释这段」：200~300 字解释（10 秒）。
2. 切「为什么」：一句因果 + 来龙去脉 + 依据；再切「前文线索」：人/物首次出现与最近提及，点一条跳回原章。
3. 演示「不剧透」：把阅读位置停在较早章节，问一个后文才揭晓的问题 → 回答明确说「前文没有提到」。
4. 进「创作」页：写一句画面 → 直接生成；再写一句 → 润色生成（补一句修改意见）；再上传一张图 → 反推出可编辑的提示词。
5. 连提三张，看底部「正在生成（1/3）」排队与图库占位块；画完长按可在图库复制提示词、存相册、删除。
6. 演示「断网不影响」：飞行模式下翻页 → 阅读正常，无任何报错弹窗；联网后位置自动同步。

## 7. 后续可加（按性价比排序）

1. **条数预算 + 白名单过滤**（已定位问题）：直接解决「解释过多」。
2. 「这本我熟」开关 + 逐词「不用解释」记忆。
3. 问书回答支持多轮追问（当前是单轮）。
4. **生图侧**：角色卡按书的目录结构分目录（已设计）、段评图按书过滤（配图页当前是全书混排）；出图后自动裁掉多余留白。
5. **生图侧**：同一段多版对比视图（现在是一张一张看），以及把「这张的提示词」直接带进创作页继续改。
